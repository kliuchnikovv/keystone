# Keystone Web MVP — бриф для дизайнера

**Статус:** v0.1
**Роль:** дизайнер UI (Figma)
**Параллельная работа:** [`frontend-brief.md`](./frontend-brief.md) — фронтендер работает по этому же скоупу.
**Контекст-документы (обязательно прочитать):**
- [`ui-design-brief.md`](./ui-design-brief.md) — общий дизайн-язык Keystone. Палитра, типографика, принципы, стилистический тон. Твоя главная библия.
- [`ui-mockups.html`](./ui-mockups.html) — черновые wireframes от предыдущей итерации.
- [`smart-home-engine-brief.md`](../../../claude/smart-home-engine-brief.md) — продуктовая рамка (можно по диагонали).

## 1. Что мы делаем

Первую живую версию мобильного/веб приложения Keystone. Ограниченный скоуп — только два экрана. Задача не «нарисовать всё приложение», а **сделать MVP, который можно показать и потрогать на реальной лампе WARMBLIXT от IKEA**.

Позже это станет мобильным приложением (React Native), но сначала — web. Дизайн должен работать в мобильных пропорциях (~390pt ширина, iOS-first).

## 2. Скоуп MVP

Только два экрана + минимально нужный набор состояний.

**Экран 1: Home**
- Приветствие + время суток.
- Кнопка «Добавить устройство» (в шапке).
- Список устройств, сгруппированный по типу.
- Empty state (когда устройств нет).
- Nav bar снизу (4 таба, но активен только «Дом»).

**Экран 2: Add Device**
- Intro (короткий, можно скипнуть).
- Scan (камера + список найденного).
- Success (прогресс commissioning + выбор комнаты).

Всё остальное (Rooms, Automations, Energy, You, Device Detail, Settings) — вне скоупа. Экраны для них рисуем в v1.1 после MVP-запуска.

## 3. Целевое устройство: IKEA WARMBLIXT

Тестовая лампа. Все дизайн-решения проверяем на ней.

- Тип: настольная декоративная LED.
- Что показываем в UI: **on/off, яркость 0–100%, цветовая температура 2200K–4000K (tunable white)**.
- Не RGB — только тёплый ↔ холодный белый. Для слайдера color temperature важна визуальная метафора «оттенок» (амбра ↔ голубоватый белый), а не цветовое колесо.

## 4. Дизайн-принципы (короткая версия)

Полностью — в `ui-design-brief.md`. Здесь пять пунктов, к которым возвращаешься при каждом решении:

1. **Ambient over listing.** Не список тумблеров, а живая поверхность.
2. **Room-first, not device-first.** Пользователь думает «свет на кухне».
3. **Intent before mechanics.** AI-предложения и сцены — перед механическим управлением. (В MVP intent-кард ещё нет, но заложи место под них.)
4. **Living, not static.** Всё анимировано и реагирует на события мгновенно.
5. **Family-safe.** Ошибки — спокойным тоном, а не красным алертом.

## 5. Визуальный тон

Задано в `ui-design-brief.md`: **живой, тёплый, цветной** (Nest / Nothing OS vibe). Не металл-и-стекло Apple TV, а мягкие градиенты, органические формы, тёплая типографика.

**Стартовая палитра** (можно уточнять):

- Background: `#141210` (тёплый near-black).
- Surface: `#1E1B18`.
- Text: `#F4EFE7` (offwhite с тёплым оттенком).
- Text secondary: `#A69F94`.
- Accent (для active state): **тёплый янтарный** `#F4A860`.
- Accent 2 (для intent-cards): терракотовый `#D96B4A`.
- Warning: охра `#E4A649`.
- Success: `#7FB069`.
- Danger: `#D45D5D`.

Тёмный режим — основной. Светлый нужен, но приоритет 2.

**Типографика:** Fraunces (display, серифный, тёплый) для заголовков + Inter (body). Табличные цифры для чисел (мощность, температура, время).

## 6. Экран Home — детальная спека

### Информационная архитектура

```
┌─────────────────────────────────┐
│ Header                           │
│   ● Доброе утро, Валерий         │
│   ● 22° · солнечно               │
│   ● [+] в правом углу            │
├─────────────────────────────────┤
│                                   │
│ Section: Свет  (2)                │
│   ┌─Tile─┐  ┌─Tile─┐              │
│   │       │  │       │              │
│   └───────┘  └───────┘              │
│                                   │
│ Section: Розетки  (2)             │
│   ┌─Tile─┐  ┌─Tile─┐              │
│   └───────┘  └───────┘              │
│                                   │
│ Section: Датчики  (пусто)         │
│   [Empty hint внутри секции]     │
│                                   │
├─────────────────────────────────┤
│ Nav bar (fixed bottom)            │
│   🏠 ⚡ ✨ 👤                        │
└─────────────────────────────────┘
```

### Header

Не sticky (при скролле уходит), но `+` кнопка добавления должна быть **всегда доступна** — либо floating action button снизу справа, либо sticky-тонкая полоска после скролла. Твоё решение.

Приветствие меняется по времени суток: «Доброе утро/день/вечер/ночь». Погода — опциональная (пока — placeholder, интеграция потом).

### Device Tile — самый важный компонент MVP

Один тайл на устройство. Живёт с приходом live-state с бэка. Тайл — не карточка-в-списке, а самодостаточный маленький «микро-виджет».

**Обязательное содержимое:**

- Иконка типа (левый верхний угол). Пока — placeholder-emoji, финальные пиктограммы отдельно.
- Название устройства.
- Комната (мелким текстом под названием). Если комнаты нет — «Без комнаты».
- Live-состояние (см. по типу).
- Основной control (см. по типу).

**Варианты по типу устройства:**

**A. Light (WARMBLIXT):**
- Toggle on/off крупный, правый верхний угол.
- Строка яркости (компактный slider) внизу тайла — только если on.
- Строка цветовой температуры — chip или мелкий label под яркостью. «2700K · тёплый».
- Когда включен — тайл **теплеет** (ambient-градиент амбры).

**B. Plug:**
- Toggle on/off крупный.
- Если есть power_meter — текущее потребление крупно (`340 W`), тонкой полосой снизу — доля от 2 кВт как визуализация.

**C. Sensor (температура, влажность):**
- Крупная цифра со значком единицы.
- Нет controls (read-only).

**D. Motion:**
- Индикатор «сейчас есть движение» или «5 мин назад».
- Точка пульсирует при активном motion.

**Состояния каждого тайла:**

- **Idle** — обычный, всё ок.
- **Active** — накрытый ambient-градиентом. Свет включён / что-то происходит.
- **Offline** — прозрачность 55%, серая точка вместо accent-цвета, надпись «недоступно».
- **Pending** — сразу после тапа, пока подтверждение с бэка не пришло (~150ms). Toggle с пониженной opacity, чтобы понятно было «в процессе».
- **Error** — тонкая коралловая обводка + subtitle «не отвечает». Не красный alert.

Все состояния — обязательны в макетах. Это те четыре карточки на весь Figma-файл, которые фронтендер положит в Storybook.

### Interactions

- Тап на toggle → мгновенное изменение состояния (optimistic).
- Тап на body тайла (не на control) → навигация в Device Detail. В MVP no-op, но заложи visual hover/press state.
- Long-press → в MVP no-op (в будущем — быстрое меню сцен).
- Slider яркости — drag или tap-to-position. Твоё решение.

### Empty state

Экран Home с нулём устройств:

```
        🕸️  (иконка большим размером)
   
   Пока ни одного устройства.
   
   Добавь первое — это займёт минуту.
   
   [ + Добавить устройство ]   ← primary CTA большая
```

Тёплый, приглашающий, а не суровый.

### Group sections

Устройства группируются по типу в MVP (не по комнатам — комнат в этой версии ещё нет).

- Заголовок секции: тип + счётчик в скобках. Например «Свет (2)».
- Если в секции 0 устройств — секция не рисуется вообще (кроме случая полного empty state).
- Порядок секций: Свет → Розетки → Датчики → Прочее.

## 7. Экран Add Device — детальная спека

Три подэкрана. Главный — второй (Scan).

### 7.1 Intro (Skippable)

Показывается только при первом Add Device, потом сохраняется флаг «не показывать снова».

- Верх: крупная иллюстрация (WARMBLIXT? общий тёплый объект? — твоё решение).
- Заголовок: «Найдём твоё устройство.»
- Подзаголовок: «Наведи камеру на QR-код или коробку. Мы также сканируем твою сеть.»
- Кнопка «Начать» (primary, крупная).
- Мелкий чекбокс: «Больше не показывать».

### 7.2 Scan — **главный экран Add Device**

Самая критичная точка UX в MVP. Тут HA сливает больше всего — 12 шагов и YAML. У нас — **один экран, всё сразу**.

**Верх (~40% высоты):**

- **Camera preview** — live-view с задней камеры (front для web-версии).
- Поверх — «прицельная рамка» для QR: 4 угловых уголка accent-цветом.
- При успешном распознавании QR — мгновенная обратная связь: уголки мигают success-цветом на 200ms, всё содержимое рамки коротко светится амброй.
- Внизу камеры — тонкий hint: «Наведи камеру на QR устройства».

**Низ (~60% высоты):**

- Section header: «Найдено рядом · N» — счётчик обновляется live.
- Список найденных устройств. Каждый элемент:
  - Иконка типа.
  - Название (модель, если известна: **«WARMBLIXT»**).
  - Транспорт (Matter, Zigbee, DIRIGERA…) — маленьким pill-бэджем.
  - Действие: кнопка «Добавить» (primary, компактная) или иконка checkmark если уже добавлено.
- **New-device highlight:** тонкая accent-полоса слева от новинки в течение 3 секунд после появления. Показывает пользователю «оно нашлось прямо сейчас».
- Разделитель. Ниже — секция «Ничего не находится?» с кнопкой «Ввести setup code вручную» — раскрывающееся поле ввода.

### 7.3 Success — прогресс + финал

После тапа «Добавить» — переход в этот экран.

**Верх:** прогресс commissioning с этапами. Live-обновление от бэка (`POST /devices/commission` возвращает stream событий).

Этапы:
1. Discovering (нашли устройство).
2. Pairing (обмен ключами Matter).
3. Verifying (первая команда — moment проверки).
4. Done.

Каждый — иконка + короткая надпись + чек-марка когда завершён.

**Финал (когда Done):**

- Крупная success-иллюстрация или чек-марка.
- Заголовок: «Готово. WARMBLIXT в твоём доме.»
- Превью-тайл того устройства (тот самый Device Tile, что на Home).
- Field/dropdown: «В какую комнату?»
  - Существующие комнаты + «Создать новую».
- Две кнопки:
  - **«Проверить»** — светит на секунду физически, для подтверждения.
  - **«Готово»** — возврат на Home.

### Failure state (важно)

Если commissioning падает:

- Не красный алерт. Тёплое сообщение: «Что-то не вышло. Проверь, что WARMBLIXT включён в розетку и лампочка мигает жёлтым — режим сопряжения».
- Кнопка «Попробовать ещё раз».
- Кнопка «Отмена».

## 8. Компонентная библиотека

Компоненты, которые дизайнер собирает в Figma-библиотеке. Каждый — с variants (состояниями).

**Атомарные:**

1. **Toggle** — маленький (в тайлах) и большой (в device detail, для v1.1).
   - States: off, on, pending, disabled.
2. **Slider (brightness)** — горизонтальный, с градиентной заливкой внутри.
   - States: value 0/25/50/75/100, disabled.
3. **Slider (color temp)** — специальный, с градиентом от тёплого-амбры до холодного-голубоватого.
   - States: values по Кельвину, disabled.
4. **Chip / Pill** — маленькая метка для типа устройства или транспорта.
5. **Button** — primary (accent-fill), ghost (только контур).
   - Sizes: small, medium, large.

**Компаунды:**

6. **DeviceTile** — 4 варианта (light, plug, sensor, motion) × 5 состояний (idle/active/offline/pending/error) = 20 вариаций. Много, но большинство переиспользуют слоты.
7. **FoundDeviceItem** — строка в списке найденного (Add Device Scan).
8. **CommissioningStep** — один шаг прогресса (icon + label + checkmark).
9. **NavBar** — 4 таба + active indicator.
10. **SectionHeader** — заголовок секции («Свет (2)»).
11. **CameraFrame** — визуальная рамка с уголками поверх camera preview.

Дополнительно (не входит в core MVP):

12. **IntentCard** — placeholder для v1.1.
13. **EmptyState** — иллюстрация + текст + CTA.

## 10. Deliverables — что от тебя нужно

Приоритетность: 1 = блокер для фронта, 2 = MVP-финал, 3 = v1.1.

### Приоритет 1 (первые 3 дня)

1. **Design tokens** — палитра, шрифты, spacing, radii в виде JSON или структурированного Figma variables file. Фронтендер копирует в `tokens.ts`.
2. **DeviceTile** — все 4 типа × 5 состояний. Figma-компонент с variants.
3. **HomeScreen** — три состояния: with-devices / empty / offline. Мобильная ширина 390pt.

### Приоритет 2 (следующие 4 дня)

4. **AddDevice Scan** — три состояния: пусто / 3 найдено / после QR-сканирования.
5. **AddDevice Intro** и **AddDevice Success** — все состояния включая failure.
6. **NavBar** — с 4 табами и активным индикатором.
7. **Component library** — атомы (Toggle, Slider, Chip, Button) в Figma с variants.

### Приоритет 3 (после MVP)

8. Скелетоны для loading-состояний.
9. Иконки — финальный набор.
10. Light mode.
11. Widgets и Apple Watch mocks.

## 11. Формат хендовера

- Figma-файл с компонентами (auto-layout, variants).
- Отдельная страница «Screens» — итоговые макеты в реальной композиции.
- Отдельная страница «Components» — все компоненты изолированно.
- Отдельная страница «Tokens» — палитра и типографика, копируемые дизайнером в JSON.

Handoff — через Dev Mode в Figma (фронтендер копирует spacing/colors оттуда).

## 12. Работа в парах — что делает фронтендер

Параллельно и не ждёт тебя:

- Настройка проекта (Vite + React + TS), CI, линтеры.
- API-клиент и подписка на live-stream от бэкенда.
- Zustand-стор для устройств.
- Технические скелетоны экранов (пустые компоненты с правильным layout, заполнятся стилями когда придут макеты).

Ты можешь параллельно и не блокировать фронт — он начинает с dev-tokens (плейсхолдеры) и переезжает на твои финальные, когда те готовы.
