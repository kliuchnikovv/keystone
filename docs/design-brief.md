# ТЗ для дизайнера приложения Keystone

Функциональная спецификация клиентского приложения к хабу Keystone. Эстетику —
типографику, палитру, иконографику, тон — решает дизайнер; этот документ
закрывает контент и поведение.

Приложение уже реализовано инженерно (Expo, iOS + Android + web, [app/](../app/)).
Задача — визуальный ре-дизайн, не изменение логики. Если что-то в этом ТЗ
покажется противоречащим фактически запущенному приложению — приложение
первично, этот документ правим.

---

## 1. О продукте

**Keystone** — локальный хаб умного дома в коробке на столе. Он управляет
Zigbee-устройствами (лампы, плаги, датчики, кнопки, термостаты) и показывает
их в Apple Home через встроенный Matter-мост. Клиентское приложение — его
«пульт»: оно живёт на телефоне (iOS, Android) и в браузере, ходит в хаб по
локальной сети (а в будущем — через облачный реле) и даёт человеку:

- посмотреть, что в доме, и переключить
- настроить правила (расписания, таймеры, if-then, сцены)
- управлять самим хабом (Wi-Fi, локация, добавить устройство, обновить)
- увидеть, что происходило в доме

**Чем это НЕ является.** Это не универсальный умный-дом-клиент (как Home
Assistant). Он работает только со «своим» хабом. У хаба нет облачного
аккаунта и регистрации — доступ через локальный токен и пиннинг сертификата.
В 90 % случаев всё приложение открывают, чтобы один раз нажать на кнопку.

**Основные принципы.**
- **Локальность — главное.** Хаб работает без интернета, приложение тоже должно (кроме экрана облачного доступа).
- **Один хаб — одно приложение.** Нет мульти-хаб-реестра. Переподключение к другому хабу — ручное.
- **Приложение не владеет состоянием.** Все данные приходят от хаба и могут поменяться в любой момент (другой клиент, физическая кнопка на устройстве, автоматизация).
- **Offline — честно показываем.** Если связи нет, не притворяемся: карточки стают приглушёнными, кнопки — некликабельными, баннер объясняет, что происходит.

## 2. Пользователь и устройства

### 2.1 Платформы

| Платформа | Статус | Что учитывать |
|---|---|---|
| iOS (iPhone 13+) | Основная | Portrait only. Dark/light mode по системе. Dynamic Type. Safe area (notch, home indicator). |
| Android (6.0+) | Основная | Portrait only. Dark/light по системе. Material 3 — не обязательно, но ожидаемо. |
| Web (Chrome, Safari, Firefox) | Второстепенная | Та же вёрстка, что на мобильном. Dark/light по системе. 360–1440 px ширины. |
| iPad / планшет | Опционально | Разметка та же, что на телефоне, с ограничением ширины контента ~500 px. |

**Темы.** И тёмная, и светлая — обязательны, переключение по системе
(вручную в приложении не меняется). Приложение не хранит пользовательских
настроек внешнего вида.

**Локаль.** Интерфейс на английском, скоро — на русском. Форматы чисел и дат
локализованные (единицы — °C и %, время — 24ч или 12ч по локали).

**Доступность.** Текст контрастный в обеих темах (WCAG AA), минимальная
кликабельная область 44 × 44 pt, VoiceOver/TalkBack-метки на всех живых
элементах (не декоративных).

### 2.2 Типы устройств

Устройства в доме умеют разные вещи. На экране «Devices» и в формах
автоматизации нужно уметь показать и ввести значение для каждого из этих
типов:

| Тип | Как показывать | Атрибуты, которые пользователь трогает |
|---|---|---|
| **Выключатель / розетка** (plug, light switch) | Карточка со свитчем | `on_off` (bool) |
| **Диммируемая лампа** | Свитч + ползунок яркости (%) | `on_off`, `brightness` (0–100 %) |
| **Лампа с CT** | То же + ползунок цветовой температуры (K) | `on_off`, `brightness`, `color_temp` (2000–6500 K) |
| **Цветная лампа (RGB)** | То же + color picker | `on_off`, `brightness`, `color_xy` или `color_temp` |
| **Умный плаг с метерингом** | Свитч + текущая мощность (W) и энергия (kWh) | `on_off`, read-only `power_w`, `energy_wh` |
| **Датчик движения** | Карточка-читалка | `occupied` (bool), + возможно температура/влажность/освещённость |
| **Датчик открытия** (контактный) | Карточка-читалка | `contact` (true = закрыто) |
| **Датчик температуры / влажности / освещённости** | Карточка-читалка с большим числом | `temperature` (°C), `humidity` (%), `illuminance` (лк) |
| **Термостат** | Карточка с текущей и целевой температурой, режимом | `setpoint` (°C), `mode` (off/heat/cool/auto), read-only `current_temp` |
| **Кнопка / сцена-свитч** | Карточка-читалка | `event` (last press type), read-only. Не управляется, только слушается |
| **Плаг с датчиком энергии (батарея)** | То же, что плаг + индикатор батареи | + `battery` (%) |

Device-type приходит с хаба; дизайн должен покрыть все перечисленные варианты.
Один «entity» в UI = одна карточка, независимо от количества атрибутов.

### 2.3 Специальные сущности («self»)

Каждый радио-чип в хабе также представлен как сущность с метриками (uptime,
heap, boot_id). Их НЕ показываем в списке устройств — они живут на вкладке
«Hub» как «состояние хаба», не как «устройство».

## 3. Навигация и карта экранов

```
                          ┌─────────────────┐
                 запуск ─▶│ ConnectScreen   │─ hub найден ─▶┐
                          │ (вход)          │                │
                          └────┬────────────┘                │
                               │                              │
                               │ хочу новый хаб               │
                               ▼                              │
                          ┌─────────────────┐                 │
                          │ SetupScreen     │─ хаб настроен ─▶│
                          │ (первая настр.) │                 │
                          └─────────────────┘                 │
                                                              ▼
                                           ┌─────────────────────────────┐
                                           │          Home (tabs)        │
                                           │  ┌────┬────┬────┬────────┐  │
                                           │  │ Dev│ Aut│ Hub│ History│  │
                                           │  └────┴────┴────┴────────┘  │
                                           └─────────────────────────────┘
```

Четыре вкладки нижнего таб-бара (одинаковый приоритет):
1. **Devices** — что в доме (default-экран после входа).
2. **Automations** — расписания, таймеры, правила, сцены.
3. **Hub** — состояние хаба, Wi-Fi, локация, Apple Home.
4. **History** — журнал событий.

Все вкладки — scrollable screens, не sub-navigation. Переходы между
вкладками мгновенные; внутри вкладки могут быть modal-формы (создание,
редактирование) — предпочтительно bottom sheets, не full-screen push.

**Таб-бар** — по соглашению платформы:
- **iOS** — плавающая пилюля: высота 60, отступ 16, ширина 100 % − 32, радиус 999,
  глиф 21, подпись 10 (как в iOS 26).
- **Android и web** — нижняя панель во всю ширину (как в макете комнаты): высота
  82 px (62 под вкладки + 20 под home-indicator), тёплая кромка сверху, глиф 22,
  подпись 10.

Активная вкладка — акцентом и весом 600 в обоих случаях.

**Заголовок экрана** — панель 52 px с заголовком 17/700 по центру и слотами
44×44 по бокам (слева — кнопка «Назад», если экран не корневой). Так оформлены
Automations, Hub и History; на Devices сверху приветствие.

**Доступ к ConnectScreen из Home:** в Hub-вкладке есть кнопка «Switch hub /
Disconnect», которая возвращает на Connect с очисткой текущей сессии.

## 4. Экран входа — Connect

**Назначение.** Указать, куда ходить. Либо приложение само нашло хаб через
mDNS и предлагает его тапнуть, либо человек вводит адрес вручную.

### 4.1 Что должно быть

- Логотип / название (место под брендинг).
- **Список найденных хабов** (title + address, обычно 0–3 штуки). Тап по
  карточке заполняет поле адреса.
- **Поле «Address»** — вручную. Поддерживает три формата:
  - `wss://192.168.0.202:8443/ws` — локально, TLS с пином.
  - `ws://keystone.local:8080/ws` — локально, без TLS (dev).
  - `https://relay.keystone.example/hub/<id>` — через облачный реле (режим **Cloud**).
  - `wss://relay.example.com:9090/tunnel/my-hub` — через свой релей (режим **Relay**).
- **Поле «Token»** — токен хаба, типа длинной случайной строки. Secret-поле
  (точки вместо символов, кнопка «показать» рядом).
- **Поле «Certificate fingerprint»** — только для `wss://`. SHA-256 вида
  `AA:BB:CC:…` (длинная шестнадцатеричная строка через двоеточия). Можно
  оставить пустым для обычных CA-сертификатов.
- Чипы режима подключения: **Local / Cloud / Relay**. Выбор меняет, какие
  поля активны. Local — всё как выше; Cloud/Relay — только адрес + токен.
- Кнопка **Connect** (primary). Проверка (адрес, токен, формат отпечатка) идёт
  по нажатию, ошибка пишется под конкретным полем.
- Ссылка **«Set up a new hub»** (secondary) → SetupScreen.
- Опционально: ссылка на инструкцию «Where do I find the token?» (ведёт на
  короткую подсказку / modal).

### 4.2 Состояния

| Состояние | Что видно |
|---|---|
| Idle | Форма; кнопка Connect активна только когда адрес + токен заполнены |
| Discovering | Над списком хабов — спиннер и текст «Searching your network…» |
| Hubs found | Список карточек; «Not seeing yours?» ссылка-подсказка под ним |
| Connecting | Полноэкранный спиннер / inline-индикатор на кнопке; форма disabled |
| Error: wrong token | Красный баннер под формой, фокус на поле Token |
| Error: untrusted (пин не совпал) | Красный баннер «This hub's certificate changed. Someone may be intercepting the connection.» + подробности |
| Error: unreachable | «Can't reach the hub. Check Wi-Fi.» + кнопка retry |
| Error: pin not supported | «This browser can't pin a certificate. Use the mobile app.» (только на web) |

### 4.3 Безопасность — важно для копирайтинга

- Поле Fingerprint НЕ заполняется ни при discover, ни при других действиях.
  Пользователь всегда вводит его сам (с консоли хаба или из QR-кода).
- Токен НЕ отправляется до того, как сертификат пройдёт пининг. Это
  невидимо для UI, но на экране должно быть явно: «The token is only sent
  after the certificate matches.»

## 5. Экран первичной настройки — Setup

**Назначение.** Один раз, когда хаб только включили из коробки.

### 5.1 Поток

1. **Код с наклейки.** Три короткие инструкции (подключиться к `Keystone-XXXX`,
   ввести код с наклейки, вернуться в приложение) и поле кода. Отдельного
   экрана «Готов?» нет — инструкция встроена в этот шаг.
2. **Связь с хабом.** Приложение подключается к `192.168.4.1:8443`; пока идёт —
   индикатор и текст «Connecting to the hub…».
3. **Выбор Wi-Fi сети.** Хаб сам сканирует эфир и отдаёт список (SSID,
   RSSI, security). Тап по сети → поле пароля. Скрытую сеть вводят руками.
4. **Передача настроек.** «Sending the settings to the hub…».
5. **Готово.** «The hub is joining Home-5G.» + пояснение, что телефон надо
   вернуть на домашний Wi-Fi, и кнопка «Connect to the hub». Перехода в
   приложение по таймеру нет — по кнопке; токен и отпечаток приходят по
   setup-каналу и в UI не показываются.

### 5.2 Особые ситуации

- **Шаг 2, iOS**, приложению не разрешён Local Network: показать на экране
  инструкцию, как разрешить (Settings → App → Local Network), и ссылку.
- **Шаг 3, не удалось**: подробная подсказка — «Check the password; make sure
  this is a 2.4 GHz or 5 GHz network your router broadcasts.»
- **Отмена** в любой момент → возврат на ConnectScreen. Приложение не
  гарантирует, что хаб вернётся сам: нужна подсказка «If the hub is still on
  its own Wi-Fi, give it 10 minutes — it will restart».

### 5.3 Что НЕ надо показывать

- Токен (его придумывает приложение, пользователь не видит).
- Fingerprint (его тоже «выучивает» приложение автоматически в этом канале).
- Технические детали TLS / mDNS.

## 6. Вкладка Devices

**Назначение.** Главный экран. 90 % открытий — «включить/выключить одну штуку».

### 6.1 Структура

```
┌───────────────────────────────────────────┐
│  [header: hub name + status indicator]    │
├───────────────────────────────────────────┤
│  [Scenes bar — горизонтальный скролл]     │
├───────────────────────────────────────────┤
│  [комната]                                │
│  [pill: «2 of 2 on · 38 W»]               │
│  [климат-плитки]                          │
│  [сетка кнопок-устройств, 2 в ряд]        │
│                                           │
│  [+ Add a device] (внизу или фикс.)       │
└───────────────────────────────────────────┘
```

### 6.1a Комнаты

Устройства сгруппированы по комнатам, и это **вычисляемое свойство, а не данные хаба**:
комната берётся из начала имени — по первому слову или фразе, которой имя начинается
(«Living room lamp» → «Living room», `kitchen_lamp` → «Kitchen»), потому что в протоколе
поля «комната» нет. Заголовок комнаты — overline, под ним — сводка, климат-плитки и сетка
кнопок; в шапке экрана — счётчик «2 rooms · 5 devices», но он появляется, только если
комнат больше одной или устройств больше одного: «1 room · 1 device» ничего не сообщает.
Если имя не задано, устройство попадает в «Unassigned».

### 6.1b Сводка комнаты

Под заголовком комнаты — одна плашка со сводкой: сколько устройств комнаты включено и
сколько они потребляют («2 of 2 on · 38 W»). Считается по тем устройствам, у которых есть
переключатель; потребление — по `power_w`. Плашка появляется, только если переключаемых
устройств в комнате больше одного: у комнаты с единственным устройством сводка «Off»
ничего не добавляет. Если переключаемых устройств нет, плашки нет.

### 6.1c Климат-плитки

Если в комнате есть датчики температуры, влажности или освещённости — карточка «Climate»
плитками: `21.5 °C · Temp.`, `48 % · Humidity`, `320 lx · Light`. Плитка есть только
для того, что устройство действительно сообщает; пустых плиток не бывает, нет датчиков —
нет карточки.

### 6.2 Scenes bar

Если у хаба есть сцены — горизонтальный ряд кнопок-пилюль над списком. Тап
по сцене мгновенно шлёт команды. После применения — короткий toast
«Applied 'Night': 5 settings sent» (или «3 sent, 1 skipped» если устройство
недоступно).

Пустой список сцен → не показывать bar вообще.

### 6.3 Device buttons

Один entity = одна кнопка в сетке (**три колонки**). **Кнопка и есть переключатель:** тап по
кнопке включает и выключает, отдельного свитча нет — лишний переключатель только мешал бы.
**Долгий тап открывает лист устройства.** Отдельной кнопки «⋯» нет: она занимала место
в кнопке, цеплялась за свайп и ничего не добавляла.

**Форма кнопки выводится из данных устройства** — в одной сетке живут три формы:

| Форма | Когда | Что внутри |
| --- | --- | --- |
| Широкая (строка) | устройство переключается и у него меньше двух показаний | иконка слева, имя и текущее значение справа |
| Квадратная | устройство без переключателя (датчик) | иконка 38×38, имя, показание |
| Вертикальная | у устройства два и более показания | иконка и имя сверху, показания снизу, первое — крупным числом |

Ячейка сетки — **треть экрана, а не половина**: кнопке, которой нечего много сказать,
хватает одной ячейки. Широкая кнопка занимает строку целиком.

**Пока палец на кнопке:**

- Палец коснулся — кнопка сразу приглушается (opacity 0.88): отклик мгновенный.
- Палец не отпускает — через 250 мс кнопка **загорается янтарём** (рамка 2 px, иконка
  залита акцентом, кнопка слегка вдавливается): человек видит, что приложение считает
  его зажатие. Ещё через 250 мс открывается лист устройства.
- Палец отпущен — кнопка вернулась в обычное состояние.

**Общее у всех кнопок:**
- Имя (от пользователя — человеко-читаемое, см. §6.3b; или системное `plug1`, или
  шестнадцатеричный id).
- Иконка типа (lamp, plug, sensor, button, …) в квадрате 36×36.
- Под именем — что устройство делает сейчас: мощность (`38 W`), яркость (`50 %`) или
  показание датчика (`Occupied`). Выключенное устройство молчит — строки нет.

### 6.3a Лист устройства

Всё, что не помещается в кнопку, живёт в листе:

- Заголовок — имя устройства, под ним — тип и состояние («Plug · On»).
- Строка «Turn off» / «Turn on» с иконкой устройства.
- Метеринг (у розетки): `Power draw 42 W`, `Energy 1.20 kWh`.
- Ползунок яркости (0–100 %) с крупными + и − для шага 10 %. Деактивирован, когда
  выключено.
- Цветовая температура — второй ползунок (2000–6500 K); цвет — «колодец», тап по
  которому открывает color picker (bottom sheet).
- Датчики: показание большим числом, «updated 12 s ago» (обновляется в живом времени),
  батарея, если есть.
- Термостат: текущая температура, уставка с ± кнопками, чипы режимов
  `off / heat / cool / auto`.
- Кнопка: «This button has no settings here — it can trigger rules.» и
  «Last pressed: 2 min ago».
- Три редких действия: Rename, Blink, Remove device.

**Клавиатура.** Когда появляется клавиатура, лист поднимается над ней на её высоту и
не перекрывает поле, в которое печатают. Поле имени получает фокус сразу (Rename открыл
лист — человек уже собирается печатать). Высота клавиатуры меряется своим кодом:
`KeyboardAvoidingView` из react-native-web не делает ничего, поэтому на вебе высота
берётся из `visualViewport`, на телефоне — из событий клавиатуры.

### 6.3b Имя устройства

Имя, которое человек задаёт сам, — **человеко-читаемое**, а не машинное:

- До **15 символов** (считаются кодовые точки: кириллица — один символ, не два).
- Пробелы разрешены — «Living room lamp» лучше, чем `living_room_lamp`.
- Буквы, цифры, пробел и знаки `. , & ' ( ) - _`; пробелов в начале и в конце быть не должно.
- Имя, похожее на идентификатор (`0x10`, `123`), хаб не принимает: иначе в консоли
  устройство нельзя адресовать по имени.
- Поле в листе: подпись «Up to 15 characters, spaces allowed. Start with a room to group it,
  e.g. Living room lamp.» Если имя не задано — устройство живёт в «Unassigned».

Имя сцен остаётся машинным (`a-z0-9_`) — сцены адресуются из консоли и в правилах.

### 6.4 Специальные состояния

| Состояние | Что видно |
|---|---|
| Хаб offline | Весь список приглушён, баннер сверху — как в §10.1 |
| Нет устройств | Иллюстрация + текст: «No devices yet. Tap below to add your first one.» |
| Устройство unreachable (чип silent) | Кнопка приглушена и пишет «offline», тап показывает toast «Device unreachable» |
| Устройство только что команду получило | Короткий визуальный пинг на кнопке (светлая обводка на 0.5 с), чтобы человек увидел что команда «пошла» |
| Rename активно | В листе открывается поле ввода + Save / Cancel. Валидация имени — §6.3b: до 15 символов, пробелы разрешены |

### 6.5 Add a device (кнопка внизу или FAB)

Тап → bottom sheet «Add a device»:
- Текст: «Press the pair button on your Zigbee device (or power-cycle it). You have 2 minutes.»
- Live countdown таймера (120 → 0 с).
- Live-список того, что присоединилось («plug1 joined, 5 s ago»).
- Кнопка Cancel.

Когда таймер истекает — закрытие окна с результатом («1 device added» или «No devices joined»).

### 6.6 Remove / Blink

В листе устройства (открывается долгим нажатием на кнопку):
- **Blink** — мигает лампой / индикатором физического устройства 10 секунд, чтобы человек нашёл, которое из них это (`identify`-команда Zigbee).
- **Remove device** — два тапа: первый открывает подтверждение «Remove plug1? This will take it off the Zigbee network and from Apple Home.», второй — выполняет.

## 7. Вкладка Automations

Четыре подраздела на одной странице (sticky-header-табы или collapsible-блоки
— на усмотрение дизайнера):

1. Scenes
2. Schedules
3. Timers
4. Rules

Каждый — список карточек с кнопкой «+ Add» в заголовке.

### 7.1 Scenes

Сцена — именованный набор команд, применяемый одним нажатием.

**Карточка сцены:**
- Имя (`Night`, `Movie`).
- Summary из 1–2 строк: «Plug1 off, Lamp1 to 30 %, Thermostat 20 °C» (сокращается с троеточием если длинное).
- Иконки участников (превью, 3–5 иконок).
- Primary action: tap-to-apply.
- Secondary action: Edit (pencil).
- Overflow menu: Delete.

**Форма «Add scene» (bottom sheet, 2 шага):**
1. **Выбор устройств и их значений.** Чеклист всех устройств (кроме read-only
   и чипов). Для выбранных — редактор значения в его единицах.
2. **Save as.** Поле «Name» (`[a-z][a-z0-9_]{0,22}`), подсказка валидации
   строгая. Опционально: кнопка «Use current state of selected devices» —
   возьмёт сейчас действующие значения вместо ручного ввода.

**Edit scene:**
- Открывается вместо выбора — сразу форма редактирования с заполненными
  значениями.
- Можно: изменить значение, удалить настройку, добавить ещё одно устройство,
  или одним нажатием «Refresh from devices» (взять текущие значения).
- Если устройство из сцены удалено с хаба — показать с пометкой «No longer
  available, will be removed on save» и дропнуть при save.
- Save → `scene.put` под тем же именем, id сцены сохраняется (расписания,
  таймеры и правила, ссылающиеся на эту сцену, продолжают работать).

**Delete scene:**
- Если сцена используется в расписании/таймере/правиле — отказ с объяснением,
  какая именно автоматизация её держит, и ссылкой на неё.

### 7.2 Schedules

Расписание — одно действие в определённое время дня.

**Карточка расписания:**
- Одной фразой: «22:00 · every day · Turn off plug1»
- Или: «30 min after sunset · weekdays · Scene Night»
- Или: «Once · 20 Oct 2026 · 19:00 · Turn on lamp1»
- Иконка: часы / закат / солнце.
- Overflow menu: Delete (двойной тап).

**Форма «Add schedule»:**
1. **Time:** либо HH:MM, либо «sunrise ± N min», либо «sunset ± N min».
   N от 0 до 180.
2. **Days:** chip-row: `daily / weekdays / weekends / custom (Mon Tue …)` /
   `once on a date` (date picker).
   Если локация не задана — chip «sunrise»/«sunset» деактивирован с tooltip
   «Set your location on the Hub tab first».
3. **Action:** two chips: «A device» / «A scene».
   - A device: выбор устройства + атрибута + значения (например, plug1 →
     on/off → off).
   - A scene: выпадашка со списком сцен.
4. Кнопка **Save**.

**Edge: once-on-date в прошлом** — Save выдаёт inline-ошибку.

### 7.3 Timers

Одноразовый отложенный запуск. Как расписание, только относительно «сейчас».

**Карточка таймера:**
- Live countdown: «in 42 min · Turn off plug1» (обновляется каждую секунду).
- Если истёк — автоматически исчезает (хаб сам удалит).

**Форма «Add timer»:**
1. **Delay:** stepper в формате Hh/Mm/Ss (например, 1h 30m). Валидация:
   минимум 1 с, максимум 24 ч.
2. **Action:** как в schedule.
3. Save.

### 7.4 Rules

If-this-then-that с временным окном, доп. условием, cooldown.

**Карточка правила:**
- Одной фразой: «When plug1 power > 1500 W, between 09:00 and 23:00, cooldown 2 min — turn off plug1»
- Или: «When occupancy becomes true — scene Evening»
- Если правило в cooldown — мелкий тег «cooling down · 42 s left».

**Форма «Add rule»:**
1. **Trigger:**
   - Entity + attribute: селектор устройства, потом его атрибута.
   - Operator: `changes` (= `always` на проводе) / `is` / `is not` / `is above` /
     `is at least` / `is below` / `is at most`.
   - Value: в единицах атрибута (bool chips для on/off, числовое поле с
     подписью единиц для чисел).
2. **Then:** two chips: «A device» / «A scene» → как в schedule.
3. **Advanced (collapsible):**
   - **Only between:** HH:MM–HH:MM, может пересекать полночь. Концы могут
     быть sunrise/sunset ±N (как в расписании).
   - **And only when:** одно доп. условие (другой entity + attr + op + value).
   - **Cooldown:** число секунд (форма вводит секунды; на проводе `cooldown_s`).
4. Save.

### 7.5 Удаление

Для всех: delete требует двух тапов. Первый — состояние карточки меняется
на «Delete?» с кнопкой «Confirm» и крестиком. Таймаут 3 с — молчит, возвращается
обратно.

### 7.6 Пустые состояния

- «No scenes yet. Create a scene to switch many devices at once.» + CTA.
- Аналогично для schedules / timers / rules.

## 8. Вкладка Hub

«Служебная» вкладка. Карточки сверху вниз, в этом порядке (так сейчас в
приложении): статус хаба → Wi-Fi → Location → Apple Home bridge → чипы →
Firmware (OTA) → Access → Hub actions.

### 8.1 Hub status

- Имя хаба, адрес.
- Общий статус-дот: healthy / degraded / offline.
- Uptime, free heap (мелким шрифтом).
- Reboot count за последние 7 дней.

### 8.2 Apple Home bridge (новое)

Эта карточка выделяется — её ищут люди, пришедшие «добавить хаб в Home».

- Заголовок: «Apple Home bridge».
- Статус-дот Matter-чипа: `● Online` (можно комиссионировать) / `● Not
  responding` (с подсказкой «Wait a minute and try again»).
- **Setup code крупным моноширинным шрифтом:** `3497-0112-332`. Тап по коду
  — копирует в буфер + toast; long-press / share-icon — iOS/Android share
  sheet.
- Инструкция в 3 строки:
  1. Open the **Home** app.
  2. Tap **+** → **Add Accessory**.
  3. Tap **More options** and pick this hub, or type the code above.
- Кнопка **Open Apple Home** (iOS deep link `com.apple.home://`), только
  на iOS.
- Если Matter-чип не online — большое предупреждение «Wait until the status
  turns green before pairing», deep link отключён.
- После успешного commissioning (хаб это понимает) — зелёная галочка
  «Added to Apple Home · N accessories visible».

### 8.3 Chips

Для каждого радио-чипа (`zigbee-c6`, `thread-c6`):
- Имя, роль, статус (online / silent / rebooting / flapping).
- Uptime, free heap, число перезагрузок, ошибки линии.
- `boot_id` и счётчики rx/tx хаб шлёт, но в UI не показываются; своей кнопки
  «Reboot chip» нет — обновление чипа живёт в карточке Firmware.

### 8.4 Wi-Fi

- Текущая сеть: SSID, RSSI (иконка силы), IP-адрес.
- Кнопка **Change network** → bottom sheet:
  - Кнопка **Scan** (хаб сам сканирует эфир).
  - Список сетей (SSID, RSSI, lock-icon).
  - Выбор сети → поле пароля.
  - Save → warning-карточка «The hub will try the new network. If it can't
    join, it'll come back to this one after 30 seconds. The app will
    reconnect itself.»
- Кнопки **Forget** в этой карточке нет: «Forget Wi-Fi» — в карточке Hub
  actions, с модальным подтверждением.

### 8.5 Location

- Текущие lat/lon (округлены до 2 знаков, ≈ 1 км).
- Sunrise/sunset сегодня (вычислено хабом).
- Кнопка **Use this phone's location** → запрос разрешения, одноразовое чтение
  с низкой точностью, запись в хаб.
- Кнопка **Edit** → ручной ввод координат.
- Кнопка **Clear**.

### 8.6 Firmware (OTA)

- Версия прошивки хаба и статус чипов (их версии хаб не сообщает).
- Кнопка **Update from URL**: выбор чипа, поля URL + SHA-256, кнопка Start.
  Прогресс в процентах виден по ходу (хаб отдаёт состояние по запросу).
  Отмены в приложении нет: прервать обновление можно только с консоли хаба
  (`ota … abort`).

### 8.7 Access

- Token: подпись «••••••••••••», кнопки **Show** и **Share**, кнопка **Change
  token** (генерирует новый; соединение рвётся, приложение переподключается с
  новым токеном).
- TLS certificate: fingerprint текстом (сокращённо) — это SHA-256 сертификата
  хаба; отдельной кнопки Regenerate нет (сертификат выпускается скриптом на
  стороне хаба).
- Remote access: **Set up relay** (URL + секрет) и **Remove relay**.

### 8.8 Hub actions (внизу)

- **Reboot** (две-тапная: «Tap again to reboot»).
- **Factory reset** (две-тапная + модальный warning: «Every device, rule,
  schedule, scene and name is forgotten, and the hub's own settings are wiped.
  This cannot be undone.»).
- **Forget Wi-Fi** (модальное подтверждение: хаб забывает сеть и открывает
  свою AP).
- **Switch hub** → ConnectScreen.

## 9. Вкладка History

Журнал того, что хаб видел и делал.

### 9.1 Структура

- Список событий, newest first, сгруппирован по дням (`Today`, `Yesterday`,
  `19 Oct 2026`).
- Live push — новые события появляются сверху с мягкой анимацией.
- В конце — кнопка «Load older» (если есть что).

### 9.2 Карточка события

Одна строка (две — если нужно для деталей):

- Иконка типа события.
- Timestamp (`14:32`).
- Текст человеческий: «plug1 turned on by a schedule», «Rule 'late evening'
  fired → Scene 'Night'», «Device plug1 unreachable», «Hub rebooted (power on)».
- Если устройство кликабельно — тап по строке фильтрует историю этим
  устройством.

### 9.3 Фильтр

- Фильтр-пилюля сверху: «All events» или «plug1 only» (с крестиком
  убрать). Выбирается тапом по карточке события или через меню.

### 9.4 Типы событий (не исчерпывающий список)

- `boot` — хаб перезагрузился, с причиной (power on / software reset / panic / brownout).
- `state` — атрибут устройства изменился (не включая power/energy spam).
- `command` — хабу приказали что-то сделать (с источником: console / app / rule / schedule / timer / scene / matter / reconcile).
- `command_failed` — команда не удалась (unreachable, timeout).
- `rule` — правило сработало.
- `schedule` — расписание сработало.
- `timer` — таймер отработал.
- `scene` — сцена применена.
- `chip` — чип онлайн/silent/rebooting/flapping.
- `reconcile` — хаб скорректировал устройство под desired state.
- `pairing` — устройство добавлено или удалено.

### 9.5 Пустое состояние

- «No events yet.» (бывает только у свежеразвёрнутого хаба).

## 10. Сквозные паттерны

### 10.1 Статус подключения — всегда виден

На всех вкладках сверху — тонкий баннер, когда что-то не так:
- `Connecting…` (жёлтый) — пока socket поднимается.
- `Reconnecting after a drop` (жёлтый) — был коннект, пропал на >35 с.
- `Not connected` (красный) — коннект не поднимается >N попыток, с
  кнопкой Retry.
- `Authentication failed` (красный) — токен не подошёл, с кнопкой «Go to
  Connect».

В Healthy-состоянии баннера нет (не занимать место ради «всё хорошо»).

### 10.2 Toasts

- Коротки (3–4 с), один одновременно.
- Используются для **фоновых** подтверждений: «Scene 'Night' applied»,
  «Device renamed», «Rule saved». После применения сцены — подробнее:
  «Applied 'Night': 5 settings sent» (или «3 sent, 1 skipped»).
- Ошибки форм — НЕ в toast, а inline у поля.
- Ошибки действий — в toast + подробность в баннере если критично.

### 10.3 Loading / spinners

- Полноэкранный spinner — только при входе и при переключении хаба.
- Inline-spinner — на кнопках, когда операция идёт на хабе (например, Save
  правила — хаб проверит, сохранит в NVS, вернёт ack).
- Timeout по операциям — 10 с, после чего ошибка «Hub didn't answer».

### 10.4 Confirm patterns

- **Безобидные** (toggle, rename, create): без подтверждения.
- **Деструктивные** (delete device/rule/scene/schedule/timer): двойной
  тап (первый тап меняет кнопку, второй выполняет).
- **Опасные** (factory reset, forget Wi-Fi): явный модальный dialog с
  текстом «This will do X. Y will happen.» и явной кнопкой Confirm.

### 10.5 Формы и валидация

- Все формы сохраняются одной кнопкой **Save**. Нет авто-сохранения.
- Валидация inline, с текстом ошибки под полем.
- Полные правила валидации на стороне хаба — одна и та же ошибка может
  прилететь после Save как ответ (например, «table_full», «read_only»).
  UI должен уметь это показать.

### 10.6 Единицы и форматирование

- Температура: `°C` (пока не локализовано на °F).
- Процент (brightness, battery, humidity): `%`.
- Мощность: `W`.
- Энергия: `kWh` (хаб отдаёт Wh, конвертируем клиентом ≥ 1000 → kWh).
- Освещённость: `lx`.
- Время: 24-часовое или 12-часовое по локали; дата: короткая локализованная.
- Длительность: `1 h 30 min`, `42 s`, `2 min 15 s`.

### 10.7 Доступность

- Темы: контраст AA, тёмная тема обязательна.
- Target size ≥ 44 pt.
- VoiceOver / TalkBack: все живые элементы озвучиваются с описанием
  состояния (не только названием).
- Dynamic Type: текст должен не ломаться вплоть до «XXL» на iOS.
- Движение: все анимации уважают prefers-reduced-motion / «Reduce Motion».

### 10.8 Палитра — настройка телефона

Палитра — это не тема хаба и не «внешний вид», а настройка приложения: её выбирает
человек. В приложении она живёт на вкладке Hub, карточка **Appearance**:

- **Sandstone** — тёплая бумага и терракотовый акцент; следует системной светлой/тёмной.
- **Ember** — тёмное стекло и янтарь; всегда тёмная.

Палитра меняет цвета, а не вёрстку: сетка устройств, сводка, климат-плитки и листы
выглядят одинаково, меняется только материал и акцент. Обе палитры проходят контраст AA.

### 10.9 Иконки

Нужны для:
- Типов устройств (10 типов, см. §2.2).
- Типов событий (12 типов, см. §9.4).
- Таб-бара (4 вкладки).
- Статусов (online/offline/silent/unreachable, healthy/degraded, Wi-Fi RSSI).
- Действий (play scene, blink, remove, rename, add).

Можно взять набор (SF Symbols на iOS — встроенные, Material Symbols на
Android/web). Если хотим один набор для всех — предложить.

## 14. Правки по факту запущенного приложения

Правило из преамбулы («если что-то противоречит фактически запущенному приложению — приложение
первично, документ правим») применено **по разным правилам для разных расхождений**:

- **Визуальные** требования этого ТЗ — источник истины, документ не трогаем: приложение приводится
  под ТЗ, формулировки в §04–§10 остаются исходными.
- **Фактические** (протокол, состав данных, поддерживаемые операции) — правятся в теле §04–§10,
  ниже таблица: что именно и почему.

### 14.1 Сделано в приложении (визуал по этому ТЗ)

| Пункт ТЗ | Что теперь в приложении |
| --- | --- |
| §04 «Connecting» во весь экран, форма disabled | форма остаётся на месте, кнопка Connect крутит спиннер, поля заблокированы |
| §04 кнопка «показать токен» | рядом с полем Token — глаз, токен можно посмотреть и спрятать |
| §04 «Can't reach the hub. Check Wi-Fi.» + Retry | красный блок под формой с этой строкой и кнопкой Retry |
| §04 ошибки: wrong token / untrusted / pin not supported | свои тексты под формой, при wrong token фокус в поле Token |
| §06 «⋯ menu → Rename / Blink / Remove» | кнопки «⋯» нет: лист с этими тремя пунктами открывается долгим нажатием на кнопку устройства |
| §06 имя устройства `[a-z][a-z0-9_]{0,22}` | человеко-читаемое имя: до 15 символов, пробелы и кириллица разрешены (§6.3b); хаб принимает такое имя и хранит его без потерь |
| §06 форма кнопки в сетке | три формы по данным устройства: широкая (строка), квадратная (датчик), вертикальная (два и более показаний); сетка из трёх колонок — кнопке с малым числом деталей хватает одной ячейки |
| §06 «эффект при зажатии» | кнопка приглушается сразу и загорается янтарём через 250 мс — человек видит, что приложение считает его зажатие |
| §06 «клавиатура не перекрывает поле имени» | лист поднимается на высоту клавиатуры (высота меряется своим кодом), поле имени получает фокус сразу |
| §06 toast «Applied 'Night': 5 settings sent» | toast после применения сцены (или «3 sent, 1 skipped») |
| §06 кнопка: «This button has no settings here…» + «Last pressed» | подсказка под именем и «Last pressed: 2 min ago» |
| §06 статус-дот слева от имени | точка: online / offline / unreachable (свой цвет и подпись для скринридера) |
| §06 «updated 12 s ago» | под показаниями датчика, время живёт (приложение помнит, когда значение изменилось) |
| §06 ползунок яркости с крупными + и − | слайдер 0–100 % с круглыми «−» и «+» по шагу 10 % (то же у CT) |
| §06 пустое состояние: иллюстрация + текст | своя иллюстрация (дом с розеткой) и «No devices yet. Tap below to add your first one.» |
| §06 Add a device — bottom sheet | кнопка «+ Add a device» внизу списка, лист с обратным отсчётом и списком присоединившихся |
| §06 unreachable → toast «Device unreachable» | тап по приглушённой карточке показывает toast |
| §06 визуальный пинг 0.5 с | светлая обводка карточки на полсекунды после отправки команды |
| §07 «первый тап меняет контрол на “Delete?”» | кнопка меняется на «Delete?» + крестик, 3 секунды на отмену |
| §08 статус-дот хаба: healthy / degraded / offline | точка рядом с именем хаба на карточке Hub status |
| §10 «Authentication failed» + «Go to Connect» | баннер с этой строкой и кнопкой «Go to Connect» |
| §10 «Not connected» + Retry | баннер с этой строкой и кнопкой Retry |
| §10 тосты «Scene 'Night' applied», «Device renamed», «Rule saved» | такие же тексты в тостах (успех — своим тоном, ошибка — красным) |

### 14.1a Переработанный экран Devices (по макету комнаты)

Пользовательский макет `project/Room.dc.html` («Гостиная») переписан в приложение
целиком: устройство теперь **кнопка в сетке**, отдельного переключателя нет.

| Что | Как теперь |
| --- | --- |
| Сетка устройств | Три колонки: иконка 36×36, имя, под ним — что устройство делает сейчас (мощность, яркость, показание). Выключенное молчит. Тап = вкл/выкл. Кнопка с малым числом деталей занимает одну ячейку (треть экрана), а не половину; широкая кнопка — строка целиком |
| Форма кнопки | Выводится из данных: широкая (строка) — переключаемое устройство, квадратная — датчик без включения, вертикальная — два и более показаний. Три формы в одной сетке, зазор 10 |
| Эффект зажатия | Палец на кнопке: сразу приглушение, через 250 мс кнопка загорается янтарём — видно, что приложение считает зажатие; ещё через 250 мс открывается лист |
| Клавиатура | Лист поднимается над клавиатурой, поле имени получает фокус сразу — перекрыть его нечем |
| Меню устройства | Кнопки «⋯» нет — лист открывается долгим нажатием (в iOS это системный long-press, на web — удержание) |
| Имя устройства | Человеко-читаемое, до 15 символов, с пробелами и кириллицей; комната выводится из начала имени (§6.3b) |
| Сводка комнаты | Плашка «2 of 2 on · 38 W» под заголовком комнаты — и только если переключаемых устройств больше одного |
| Климат | Карточка «Climate» плитками: температура, влажность, освещённость — только то, что датчики реально сообщают |
| Лист устройства | Всё остальное: вкл/выкл, метеринг, яркость, цвет, уставка, режимы, показания, Rename / Blink / Remove |
| Палитра | Настройка телефона: Sandstone (по системе) и Ember (тёмное стекло, янтарь). Выбор — Hub → Appearance |
| Таб-бар | iOS — плавающая пилюля (как в спеке и в iOS 26), Android/web — нижняя панель во всю ширину из макета (82 px, тёплая кромка сверху, глиф 22, подпись 10) |
| Заголовки экранов | Верхняя панель 52 px, заголовок 17/700 по центру — на Automations, Hub и History |
| Радиус карточек | 22 в палитре Ember, 18 в Sandstone (`Theme.cardRadius`) |

Всё, что раньше жило в карточке устройства (слайдеры, счётчики, показания, Rename),
переехало в лист; на кнопке осталось только то, что видно с одного взгляда.

### 14.1b Экран Connect в том же языке

Последний экран, который оставался в старой вёрстке, переведён на язык макета:

| Что | Как теперь |
| --- | --- |
| Панель сверху | 52 px, заголовок «Connect» 17/700 по центру, слева — «Назад» (если есть куда возвращаться) |
| Форма | Стеклянные карточки: «Hubs on this network», «Connection», «Token», «Certificate fingerprint (SHA-256)»; у каждой маленькая строка-имя с иконкой |
| Найденные хабы | Строка-карточка: иконка, имя, адрес и «encrypted / not encrypted» |
| Режим | Чипы-пилюли Local / Cloud / Relay (те же, что в автоматиках) |

| Кнопки | Connect — primary 15/600; «Set up a new hub» — тихий текст с подсказкой |

Логика экрана не менялась: те же поля, та же проверка, те же тексты ошибок и тот же
`webtoken`/отпечаток. Форма теперь прокручивается — раньше длинная на длинном телефоне
обрезалась.

### 14.2 Правлено в теле документа (факты)

| Пункт ТЗ | В приложении на самом деле | Что делаем |
| --- | --- | --- |
| §04 relay = `https://…/hub/<id>` | `https://…/hub/<id>` — это режим Cloud; Relay — `wss://relay…/client/<hub>` | исправлено в §04 |
| §05 шесть шагов, экран «Готов?», прогресс 30 с | пять шагов, инструкция встроена в первый, ожидание «about half a minute» | исправлено в §05 |
| §06 «power: 42 W» и «today: 1.2 kWh» | `power_w` — мгновенная мощность, `energy_wh` — накопительный счётчик; «за сегодня» хаб не считает | исправлено в §06 |
| §06 одна карточка = одна сущность | так же, но устройства сгруппированы по комнатам (комната выводится из начала имени — первого слова или фразы; в протоколе поля нет) | исправлено в §06 (добавлен раздел «Комнаты») |
| §07 оператор `always` | «changes» в приложении — это и есть `CmpOp::Always` на проводе | исправлено в §07 |
| §08 карточка чипа: boot_id, rx/tx, «Reboot chip» | хаб эти поля шлёт, в app-протоколе их нет; перезагрузки отдельного чипа пока нет | осталось за консолью хаба (правка протокола) |
| §08 OTA: отмена загрузки | хаб умеет `ota abort` в консоли, в app-протоколе операции нет | осталось (правка протокола) |
| §08 Access: «Regenerate» сертификата | сертификат перевыпускается скриптом на хосте, из приложения — только показать fingerprint | исправлено в §08 |

### 14.3 Что требовало бэкенда — и сделано

OTA из приложения, Reboot, Factory reset, Forget Wi-Fi, карточка Access (токен / fingerprint /
remote access): новые `req`-операции в `core/include/core/app_requests.hpp` плюс их разбор в
`firmware/brain-s3/main/main.cpp`. Описаны в `docs/app-protocol.md` §5.
