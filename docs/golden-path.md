# Золотой путь: из коробки в дом

Один сценарий, ради которого всё и делается: **человек, у которого есть только коробка,
телефон и домашний Wi-Fi, получает работающий дом** — без ноутбука, без консоли, без
наших инструкций на экране.

Два варианта прохождения:

- **A. Получатель** — у него нет консоли, только коробка и этикетка.
- **B. Мы** — то же самое, плюс диагностика с консоли.

## Что нужно

| | |
|---|---|
| Железо | хаб (мозг + Zigbee C6 + Matter C6), включённый в розетку |
| Этикетка | setup code и Matter code — `scripts/make-label.sh` |
| Телефон | iOS или Android |
| Wi-Fi | **только 2.4 ГГц** (ESP32-S3 и ESP32-C6 не умеют 5 ГГц) |
| Устройства | то, что добавляем в дом |

## A. Получатель

### 1. Включить

Воткнули в розетку. Хаб поднимает свою точку доступа **`Keystone-XXXX`** (последние
два байта MAC):

- сразу, если в нём нет сохранённой сети;
- через 10 минут без соединения, если сеть была (роутер сменили, хаб переехал).

Имя сети и код видно на наклейке (setup code) и в консоли (`setup`).

### 2. Телефон входит в точку доступа

В настройках Wi-Fi выбрать `Keystone-XXXX`, пароль — **setup code с этикетки**.
iOS спросит, переключиться ли на сеть без интернета — согласиться.

Телефон теперь в сети самого хаба. Хаб доступен как `https://192.168.4.1:8443`.
Сертификат у него свой (самоподписанный), приложение его пиннит — при первом
подключении показывает отпечаток, который человек сверяет с тем, что на экране.

### 3. Приложение подключает хаб к домашней сети

Приложение спросит **setup code** (с этикетки). После этого клиент, вошедший по
коду, может ровно две вещи: `wifi.scan` (список сетей) и `setup.apply` (имя сети,
пароль и долговременный токен приложения). Ничего больше.

Выбрать домашнюю сеть, ввести её пароль. Приложение само придумывает токен и
уходит с ним из setup-режима.

> **Если домашней сети нет в списке — она только 5 ГГц.** Хаб её не увидит и не
> сможет подключиться. Нужна сеть 2.4 ГГц (в роутере это «Смешанный» или «2.4 ГГц»).

### 4. Хаб в сети

Хаб подключился, точка доступа повисит ещё 60 секунд и закроется. Приложение находит
хаб по mDNS (`keystone.local`) или по адресу, который получило.

### 5. Устройства

- **Zigbee:** в приложении «Добавить устройство» открывает окно в 1–2 минуты на
  Zigbee-чипе. Устройство в этот момент добавляется в сеть, объявляет себя и
  присылает состояние.
- **Matter:** сущности хаба зеркалятся в Apple Home как bridged-эндпоинты.

### 6. Apple Home

В Home: **+ → Ещё → Light** (или хаб в списке аксессуаров) → ввести Matter code с
этикетки → хаб и его устройства появляются.

### Готово

Должны работать: переключение из приложения и из Apple Home, правила, сцены,
расписания, таймеры. Имя устройства в обоих интерфейсах совпадает.

## B. Диагностика с консоли

| Команда | Что показывает |
|---|---|
| `setup` | состояние точки доступа, её имя и код |
| `setup on` | открыть точку доступа сейчас (держится, пока не `setup off`) |
| `wifi_status` | подключён ли хаб к сети, по какому адресу |
| `wifi_scan` | сети вокруг (видны только 2.4 ГГц) |
| `wifi_forget` | стереть сохранённые credentials (хаб откроет точку доступа) |
| `home` | все сущности и их последние значения |
| `chips` | оба сопроцессора, их телеметрия и состояние |
| `events [n]` | последние события (то же, что «История» в приложении) |
| `pair [sec]` | открыть сеть Zigbee для добавления (по умолчанию 180 с) |
| `unpair <id>` | убрать устройство из сети |
| `identify <id>` | помигать светодиодом устройства 10 с |
| `name <id> <имя>` | дать устройству имя (видно и в Apple Home) |
| `rule`, `at`, `in`, `scene` | правила, расписания, таймеры, сцены |
| `desired` | что хаб последним раз просил у устройств |
| `time`, `tz` | часы и часовой пояс (нужны для расписаний) |
| `heap` | свободная память |
| `webtoken` | токен приложения (без аргументов — только статус) |
| `relay [<url> <secret>]` | туннель к релею (удалённый доступ) |
| `led [on\|off]` | статусный светодиод: зелёный — норма, жёлтый — деградация, красный — нет сети |

## Если не работает

| Симптом | Причина | Что делать |
|---|---|---|
| В списке Wi-Fi телефона нет `Keystone-XXXX` | точка доступа не открыта | `setup on`; на телефоне выбрать диапазон 2.4 ГГц |
| Точка есть, но `192.168.4.1` не отвечает | телефон не в сети точки; либо изоляция клиентов на роутере | переподключиться к `Keystone-XXXX`; проверить, что телефон в той же сети |
| Домашней сети нет в списке приложения | сеть только 5 ГГц | включить 2.4 ГГц на роутере |
| `setup.apply` вернул ошибку | неверный пароль сети или сеть вне диапазона | `wifi_scan` с консоли и проверить |
| Хаб в сети, но приложение его не видит | mDNS не проходит через роутер | ввести адрес хаба вручную (`wifi_status`) |
| Устройство не появилось | окно добавления не открыто | `pair 60` и добавить устройство в этот минуту |
| Устройство появилось, но не в Apple Home | Matter-чип не поднял эндпоинт | `chips` — оба чипа должны быть `ready` |
| В Apple Home хаб есть, а устройства нет | зеркало не создалось | `home` — есть ли сущность; `events` — что прислал Matter-чип |
| Всё работает, но расписания не срабатывают | не задана зона времени или часы не синхронизированы | `tz <posix_tz>`, потом `time` |

## Отдельно: Matter code и test DAC

Matter code на этикетке — из тестового DAC (`3497-0112-332`): в Apple Home хаб будет
помечен как «несертифицированный аксессуар». Для демо одному человеку это нормально,
и это надо сказать вслух. Свой DAC на устройство — отдельная история.
