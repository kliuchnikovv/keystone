# Прошивка хаба агентом — промпт и чек-лист

Документ для двух сторон:

* **человек** — что нужно подготовить и что от него требуется, чтобы агент мог прошить;
* **агент** — готовый промпт (копипаста) плюс шпаргалка команд и форма отчёта.

Прошивка — это последний шаг перед проверкой на железе. Сама по себе она ничего не
проверяет: ценность в том, что после неё хаб отвечает, а чипы видны в `chips`.

## 1. Что нужно от человека

### 1.1 Платы и порты

Три платы, у каждой **свой USB-C** (см. [hardware-wiring.md](hardware-wiring.md)):

| плата | кто это | чип | USB | порт (macOS) | порт (Linux) |
|---|---|---|---|---|---|
| `brain-s3` | мозг: реестр, правила, Wi-Fi, веб-сервер приложения | ESP32-S3-Zero | USB-C | `/dev/cu.usbmodem*` | `/dev/ttyACM*` |
| `zigbee-c6` | координатор Zigbee, chip 0x01 | ESP32-C6-DevKitC-1 | USB-C | `/dev/cu.usbmodem*` | `/dev/ttyACM*` |
| `thread-c6` | мост Matter over Thread, chip 0x02 | ESP32-C6-DevKitC-1 | USB-C | `/dev/cu.usbmodem*` | `/dev/ttyACM*` |

**Порт не угадывать.** Номер в имени меняется при переподключении (`1101` → `2101`).
Определить порт — `esptool.py -p <ПОРТ> chip_id`, сверить с тем, что человек назвал.
Если порт не открывается — попросить переподключить USB, а не гадать.

### 1.2 Питание

Все три платы питаются от 5V шины мозга, GND общий. При прошивке C6 **отключить USB
мозга** (иначе на шине два источника 5V). Либо — питаемый USB-хаб с отдельными
USB-линиями на каждую плату, тогда переподключать не нужно.

### 1.3 Инструменты на машине агента

| для чего | что нужно |
|---|---|
| `brain-s3` | PlatformIO (`pio run -t upload`) **или** ESP-IDF 5.5 (`~/esp/esp-idf`) |
| `zigbee-c6` | ESP-IDF 5.5 (нужен Zigbee SDK из managed-компонентов) |
| `thread-c6` | Docker с образом `espressif/esp-matter:release-v1.6_idf_v5.5.5` (~13 GB развёрнутый — **нужно место на диске**) + `esptool.py` на хосте |
| проверка | `python3 -m pip install esptool` (или `esptool.py` из IDF), `pyserial` |
| приложение | Node ≥ 22 в `app/` (для `hub-check`) |

Docker на macOS **не пробрасывает USB** — образ только собирает, прошивает хостовый
`esptool.py`.

### 1.4 Данные, без которых проверка неполна

* SSID/пароль домашней Wi-Fi (2.4 ГГц) — иначе хаб не поднимется в сеть;
* токен приложения: на консоли мозга `webtoken <token>`;
* адрес мозга в сети (`wifi_status`) — для `hub-check`;
* устройства для проверки: розетка IKEA INSPELNING, лампочка, Matter-устройство;
* Matter-чип должен быть уже скомиссионирован в Apple Home ранее (иначе эндпоинты
  не появятся) — либо это ожидаемо и фиксируется как «не проверялось».

## 2. Промпт для агента (копипаста)

```text
Ты прошиваешь хаб keystone и проверяешь, что он ожил. Репозиторий:
/Users/kliuchnikovv/go/src/github.com/kliuchnikovv/keystone (на Linux-хосте —
путь, который даст человек). Общаемся на русском.

ЖЕЛЕЗО (три платы, у каждой свой USB-C):
  brain-s3   — мозг (ESP32-S3-Zero),      порт <ПОРТ_МОЗГА>
  zigbee-c6  — координатор Zigbee (0x01), порт <ПОРТ_ZIGBEE>
  thread-c6  — мост Matter (0x02),        порт <ПОРТ_THREAD>
  (порты вида /dev/cu.usbmodem101 или /dev/ttyACM1 — уточни у человека, если не совпадают)

ЗАДАЧА:
  1. Собрать нужные прошивки и прошить платы (порядок и команды — в docs/flash-hub-agent.md,
     прочитай файл целиком).
  2. Проверить, что мозг жив, оба сопроцессора видны и отвечают.
  3. Отчитаться по форме из раздела 4 этого документа.

ЖЁСТКИЕ ПРАВИЛА:
  * Порт не угадывать. Сначала `ls /dev/cu.usbmodem*` (macOS) или `ls /dev/ttyACM*` (Linux),
    потом `esptool.py -p <ПОРТ> chip_id` — сверить, что это та плата. Не нашёлся порт →
    попросить человека переподключить USB, а не пробовать другие наугад.
  * НИКОГДА не запускать `erase_flash`: там NVS (сохранённая Zigbee-сеть, токен
    приложения, Wi-Fi, правила, расписания). Обычная прошивка не трогает NVS.
  * При прошивке C6 отключить USB мозга (на шине 5V не должно быть двух источников).
    Прошил C6 → верни питание как было.
  * Сначала сборка, потом прошивка. Сборка красная — остановиться, доложить, не прошивать.
  * Ничего не коммитить и не пушить. Секреты (firmware/*/main/hub_identity.cpp,
    relay_identity.h, wifi_secrets.h, .env) в git не попадают.
  * Один шаг за раз, лог целиком, никаких догадок в отчёте: что сделал — что увидел.
  * Ничего не «чинить» в репозитории по ходу: если для прошивки нужна правка кода —
    описать её в отчёте и остановиться.
  * Токен, пароль Wi-Fi и отпечаток сертификата в отчёт не копировать — только факт
    «проверено / не проверено».

ПРОВЕРКА (после прошивки, по очереди):
  1. Мозг: открыть консоль UART0 (115200), перезагрузить, убедиться, что он дошёл до
     «Wi-Fi up» и поднял веб-сервер.
  2. `chips` — оба сопроцессора должны быть ready, с телеметрией (heap, uptime, boot_id).
     Если чип молчит — чип не прошит, не в той сети или UART не разобран.
  3. `home` — сущности и значения (устройства должны появиться после ре-декларации).
  4. `heap` — свободная память мозга.
  5. `npm run hub-check -- --url wss://<АДРЕС>:8443/ws --token <ТОКЕН> --fingerprint <ОТПЕЧАТОК>`
     из `app/` — 31 проверок по TLS (или `--url ws://<АДРЕС>:8080/ws`, если TLS не настроен).
  6. Если прошивался thread-c6: убедиться, что мост поднялся (Apple Home видит хаб).
  7. Новое поведение Matter-пути: `matter.commission` с заведомо мусорным payload →
     ждать ответа; живой Matter-чип без комиссионера должен ответить `unsupported`
     (не `timeout`). Зафиксировать, что именно ответил хаб.
```

## 3. Шпаргалка команд

### 3.1 Определить порт

```bash
ls /dev/cu.usbmodem*        # macOS
ls /dev/ttyACM*            # Linux
esptool.py -p /dev/cu.usbmodem1101 chip_id
```

### 3.2 brain-s3 (мозг)

```bash
# PlatformIO (порт переопределяется флагом, в platformio.ini он зашит на 101):
cd firmware/brain-s3
pio run -t upload --upload-port <ПОРТ>

# или нативным ESP-IDF 5.5:
source ~/esp/esp-idf/export.sh
cd firmware/brain-s3 && idf.py -p <ПОРТ> build flash
```

### 3.3 zigbee-c6 (координатор)

```bash
source ~/esp/esp-idf/export.sh
cd firmware/zigbee-c6
idf.py set-target esp32c6        # первый раз
idf.py -p <ПОРТ> build flash
```

Нужен Zigbee SDK (`espressif__esp-zigbee-lib` + `espressif__esp-zboss-lib`) — PlatformIO
из-за этого не годится.

### 3.4 thread-c6 (мост Matter)

Сборка — в Docker (образ ~13 GB), прошивка — хостовым esptool:

```bash
scripts/matter-build.sh thread-c6            # соберёт в firmware/thread-c6/build

cd firmware/thread-c6/build
esptool.py --chip esp32c6 -p <ПОРТ> -b 460800 write_flash $(cat flash_args)
```

`flash_args` генерирует сборка — **не пиши смещения руками**: у thread-c6 своя
partition table (`0xc000`), у zigbee-c6 своя (`0x8000`), ошибиться = brick.

### 3.5 Консоль мозга

115200 на UART0 мозга (USB-Serial/JTAG). Команды: `chips`, `home`, `heap`, `events`,
`webtoken`, `wifi_status`, `time`, `tz`, `led`, `relay`.

### 3.6 Проверка из приложения

```bash
cd app
npm install
npm run hub-check -- --url wss://<АДРЕС>:8443/ws --token <ТОКЕН> --fingerprint <ОТПЕЧАТОК>
```

Отпечаток сертификата печатает `webtoken` на консоли мозга.

## 4. Отчёт агента (форма)

```
ПОРТЫ
  brain-s3:  <порт>  chip_id <...>   прошит: да/нет   команда: <...>
  zigbee-c6: <порт>  chip_id <...>   прошит: да/нет   команда: <...>
  thread-c6: <порт>  chip_id <...>   прошит: да/нет   команда: <...>

СБОРКА
  brain-s3:  ok / ошибка (<что>)
  zigbee-c6: ok / ошибка (<что>)
  thread-c6: ok / ошибка (<что>)

ПРОВЕРКА
  консоль мозга: поднялся Wi-Fi: да/нет, адрес: <...>
  chips: <две строки — chip, состояние, heap, boot_id>
  home: <сколько сущностей, имена>
  heap мозга: <...>
  hub-check: <N>/<M> (TLS: да/нет)
  thread-c6 в Apple Home: виден / не виден / не проверялось
  matter.commission с мусором: ответ хаба <unsupported | timeout | ...>  (ожидается unsupported,
    если Matter-чип жив)

НЕ ПРОВЕРЕНО
  <что осталось: устройства, которых не было под рукой; функции без железа>

ПРОБЛЕМЫ
  <что не получилось и что нужно от человека>
```

## 5. Чего агент не делает

| нельзя | почему |
|---|---|
| `erase_flash`, `erase_region` | стирает NVS: Zigbee-сеть, токен, Wi-Fi, правила |
| прошивать «наугад» по порту | можно затереть не ту плату (у esp32c6 и esp32s3 разные чипы, но неверная плата — это испорченный хаб) |
| коммитить секреты | `hub_identity.cpp`, `relay_identity.h`, `wifi_secrets.h`, `.env` — вне git |
| пушить изменения | правки в репозитории — отдельная задача, с ревью |
| менять код «по ходу» | прошивка не повод для правки; правки — отдельным коммитом с тестами |
| трогать `firmware/brain-s3/sdkconfig.brain-s3` | PlatformIO перегенерирует его под свой IDF; коммит этих churn-ов — откат конфигурации |
