# Keystone — UI Design Brief

**Статус:** v0.1, entry point для дизайнера
**Аудитория документа:** дизайнер + продакт. Инженерия смотрит, но не диктует.
**Родительские документы:**
- [`smart-home-engine-brief.md`](./smart-home-engine-brief.md) — продуктовая рамка
- [`go-core-spec.md`](./go-core-spec.md) — техническая архитектура ядра
- [`ux-automations-ai-first.md`](./ux-automations-ai-first.md) — экран автоматизаций
- [`ui-mockups.html`](./ui-mockups.html) — HTML-наметки ключевых экранов (в этой же папке)

## 1. Продуктовый контекст (короткая версия)

Keystone — универсальный движок умного дома, замена Home Assistant / Apple Home / Google Home. Работает локально на Raspberry Pi (позже — свой хаб). Целевая аудитория — **mass market**: люди, у которых сейчас Apple/Google/Homey, но хочется универсальности без технарской сложности.

Ключевое обещание в UX: **«открой приложение — сразу увидишь, что происходит в доме. Дальше — только тап»**. Никакого YAML, никаких списков карточек в стиле HA-админки.

## 2. Позиционирование против конкурентов

- **Apple Home** — красиво, но лочит экосистему и статично (просто список тумблеров по комнатам).
- **Google Home** — категории, поиск, зависит от облака.
- **Home Assistant** — мощно, но выглядит как admin-панель. Пользователь ощущает себя админом собственной квартиры.
- **Homey** — красивый премиум, но закрытая экосистема.

Наша визуальная и UX-территория: **живой, тёплый, дышащий дом на экране**. Как погодное приложение реагирует на погоду за окном — так наше приложение реагирует на состояние комнат.

## 3. Design principles

Пять принципов, к которым возвращаемся при любом решении.

**1. Ambient over listing.** Первый экран — план квартиры, где комнаты «живут» и меняются. Не список устройств. Список — во втором уровне.

**2. Room-first, not device-first.** Пользователь думает в терминах «свет на кухне», не «bulb-hue-abc123». Устройства сгруппированы по комнатам и всегда упоминаются через комнату.

**3. Intent before mechanics.** Наверху экрана — предложения того, что *вероятно* хочешь сделать в этот момент («доброе утро»/«ушёл»/«уснуть»). Механическое управление ниже.

**4. Living, not static.** Приложение анимировано и реагирует на события мгновенно. Открытие двери — мерцающая точка. Движение — плавная волна. Изменение света — плавный градиент. Не UI, а зеркало пространства.

**5. Family-safe.** Если что-то важное сломалось (свет в спальне не отвечает, замок не заперт) — это видно с первого экрана, но без агрессии. Спокойное предупреждение, а не красный алерт с восклицательным знаком.

## 4. Визуальный тон

Выбранное направление: **живой, тёплый, цветной** (Nest / Nothing OS vibe). Не металл-стекло-строгость, а мягкие градиенты, органические формы, тёплая типографика.

**Настроение референсов:**
- Погодные приложения нового поколения — Weather Line, Carrot, Not Boring Weather.
- Nothing OS — dot matrix, но с теплом.
- Google Nest Hub UI — тёплые градиенты, крупные тайлы.
- Rams-style Braun — приземлённая функциональность, но без индустриализма.

**Что НЕ хотим:**
- «Умный дом»-клише — синие неоны, глиттер, футуризм.
- Индустриальный/технический look — не выглядим как ProTools.
- Overload скевоморфизма — не пытаемся рисовать «настоящую» лампу.

## 5. Палитра (стартовая)

Задача дизайнера — привести к финальной палитре и в light, и в dark. Ниже — направления, не финал.

### Тёмный режим (основной, ~70% использования)

Дизайним под тёмный первым — по статистике smart-home apps открывают чаще вечером/ночью, и тёмный лучше передаёт «свет включён/выключен» в самой поверхности.

- Background: тёплый near-black `#141210` (не чистый #000 — теплеет к коричневому).
- Surface: `#1E1B18` для тайлов.
- Text primary: `#F4EFE7` (offwhite с тёплым оттенком).
- Text secondary: `#A69F94`.
- Accent (основной): **тёплый янтарный** `#F4A860` — используется для «активного» состояния (свет включён, устройство активно).
- Accent (secondary): мягкий терракотовый `#D96B4A` — для акцентов в intent-cards.
- Success (реже): травяной зелёный `#7FB069`.
- Warning: тёплый охра `#E4A649` — предпочтительнее жёлто-оранжевого, чтобы не путать с accent.
- Danger: приглушённый коралловый `#D45D5D` — не чистый красный.

### Светлый режим

Кремово-белая база, а не «чистый» белый:
- Background: `#FBF7F0`.
- Surface: `#FFFFFF` с тонкой тёплой тенью.
- Text primary: `#2A2521`.
- Accents те же, что в тёмном.

Оба режима — переключаются автоматически по системе + опция «Auto по времени» (тёмный после заката локально).

## 6. Типографика

- Основной шрифт: **Inter** (variable) или **Söhne** — тёплый гротеск с хорошей читаемостью на маленьких экранах и планшетах.
- Числа (энергопотребление, температура): **variant с tabular numerals**, чтобы не «прыгали» при обновлении.
- Иерархия — крупные шаги (не 10 уровней): `Display 32 / Title 22 / Body 15 / Caption 12`. Только четыре размера.
- Weight: 400 (body), 500 (labels), 600 (titles). Bold используется скупо.

## 7. Информационная архитектура

Четыре корневых раздела. Не пять. Не шесть.

```
[🏠 Home]  [⚡ Energy]  [🤖 Automations]  [👤 You]
```

- **Home** — ambient view квартиры + intent-cards. Дефолтный экран.
- **Energy** — потребление (важно для нас, у пользователя всё равно есть INSPELNING-like розетки).
- **Automations** — списки правил, промпт «что автоматизировать», proactive suggestions.
- **You** — профиль, доступ семьи, настройки, интеграции, обновление.

**Что убрано намеренно:**
- Раздел «Rooms» отдельно — комнаты открываются тапом с Home.
- Раздел «Devices» отдельно — устройства открываются тапом с комнаты.
- «Search» вверху — вместо этого есть spotlight-жест (свайп вниз с Home).

## 8. Ключевые экраны — детально

### 8.1 Onboarding (первые 3 минуты)

Пять экранов. Каждый — одно действие.

1. **Welcome** — «Здравствуй. Давай найдём твой Keystone-хаб.» Одна кнопка «Начать».
2. **Discover hub** — BLE-скан. Прогресс кольцом. Найден хаб → одна кнопка «Это он».
3. **Wi-Fi** — вводим credentials в шаг мастера. Опция «использовать текущую сеть iPhone» (Apple-style handoff).
4. **Rooms** — «Сколько комнат у тебя дома?» Ставим 3–5 preset (гостиная, спальня, кухня, ванная, детская) с иконками. Можно добавить/убрать.
5. **First device** — «Давай добавим первое устройство». Открывается Add Device flow (см. 8.5). После первого success — «Готово, попробуй нажать сюда» → тап-таск, устройство включается визуально.

**Тон:** «мы вместе делаем твой дом умным», не «конфигурируем систему». Ни слова про «commissioning», «pairing», «network topology».

### 8.2 Home (главный экран)

Верхняя часть — приветствие + погода (2 строки, крупно).

Средняя часть — **ambient view комнат**. Каждая комната — тайл с текстурой, отражающей её состояние в реальном времени:
- Свет включён → мягкое янтарное свечение внутри тайла (не яркая кнопка «ON»).
- Никого нет → тайл выглядит спокойнее, темнее.
- Движение → короткая волна/точка.
- Открытая дверь/окно → индикатор contact-датчика в углу.
- Аномальное потребление → тонкая обводка охрой.

Тайлы неровной сетки — гостиная крупнее, ванная меньше. Отражает важность и частоту использования.

Ниже комнат — **intent-cards** (1–2 штуки). Что показывать зависит от времени и паттернов:
- Утро: «Доброе утро — включить сценарий утра?»
- Обед: «Никого нет дома — выключить всё?» (когда presence-detection в бэкенде подтвердит)
- Вечер: «Уснуть — приглушить свет, закрыть шторы, поставить будильник?»

Внизу — nav bar.

**Взаимодействия на Home:**
- Тап на комнату → Room detail (8.3).
- Долгий тап → быстрое меню (свет вкл/выкл всей комнаты, сцены).
- Свайп вниз сверху → spotlight-поиск («выключи свет в спальне»).
- Свайп вправо-влево между экранами nav не делаем — nav bar статичен.

### 8.3 Room detail

Открывается тапом с Home. Как выглядит:

- Крупный header с именем комнаты и её текущим состоянием («Гостиная · 22°C · 3 устройства активны»).
- **Ambient view комнаты крупно** (если план квартиры доступен — детализируется до этой комнаты; иначе — стилизованное представление).
- Ниже — сцены комнаты («Кино», «Работа», «Уснуть») как chip-buttons.
- Ещё ниже — устройства комнаты как inline-controls (не карточки в списке, а компактные ряды с уместным control):
  - Свет — слайдер яркости в строке.
  - Розетка — переключатель + текущее потребление.
  - Датчик температуры — просто число, крупно.
  - Датчик движения — «последнее движение 3 мин назад».

Устройства *не* показываются как одинаковые прямоугольники-карточки — каждый тип имеет своё компактное представление, оптимизированное под свою функцию.

### 8.4 Device detail

Ты уже редко сюда заходишь — в 80% случаев управление идёт с Room. Но экран нужен для:
- История срабатываний (когда включался/выключался).
- Автоматизации, в которых устройство участвует.
- Настройки устройства (переименовать, переместить в другую комнату, удалить).
- Диагностика (проблемы с соединением, обновление firmware).

Верх — крупный main control (для лампы это слайдер яркости + color picker; для розетки — большая on/off + power reading).

Ниже — collapsible sections: History / Automations / Settings. По умолчанию — свёрнуты.

### 8.5 Add Device (критично — тут HA сливает больше всего)

Один экран. Не мастер из 12 шагов.

- Сверху — большая инструкция: **«Просто наведи камеру на QR-код или коробку устройства»**.
- Live camera preview занимает ~40% экрана.
- Параллельно с камерой идёт mDNS/BLE/Zigbee-scan — снизу список найденных устройств появляется в реальном времени.
- Тап на найденное → «В какую комнату?» → добавлено. Всё.

**Ни одного шага «выберите бренд из 200».** Ни одного YAML. Если устройство не распозналось автоматически — есть кнопка «Не нашёл» → отсылает в чат с поддержкой / AI-помощником, который спрашивает по-человечески.

### 8.6 Automations (см. отдельный доc)

Основное решение зафиксировано в [`ux-automations-ai-first.md`](./ux-automations-ai-first.md). Ключевое:
- Верх экрана — большое поле промпта «Что автоматизировать?» (голос + текст).
- Ниже — proactive suggestions (карточки от pattern-detector).
- Ещё ниже — активные автоматизации как natural-language карточки, а не блочные диаграммы.

### 8.7 Energy

Родная сильная сторона (у нас есть INSPELNING-подобные розетки с реальным энергомониторингом).

- Верх — текущее потребление всей квартиры (крупная цифра, тёплый градиент активности).
- Ниже — top-3 потребителя прямо сейчас.
- График за сегодня/неделю/месяц.
- Прогноз счёта, если пользователь ввёл тариф.
- Аномалии («холодильник тянет больше обычного») — сюда же.

Здесь допустима большая плотность данных, но всё равно spatial: график анимируется, категории отдельные.

### 8.8 You

Профиль, доступ семьи (см. family-mode ниже), настройки, backup, remote access, интеграции, обновление ПО.

Family mode: возможность создать «профили» членов семьи с разным набором доступных комнат/устройств. Гость видит только свет и климат гостиной; ребёнок не видит замки; родитель — всё. Не «permissions» в админ-стиле, а *разные view* внутри одного приложения.

## 9. Компонентная библиотека — набросок

Общие мысли, дизайнер собирает финальный список.

### Тайлы

- **RoomTile** — базовый тайл комнаты с ambient-заливкой. Три размера: S / M / L.
- **DeviceTile** — редко используется на Home; больше внутри Room detail.
- **StatTile** — крупная цифра + единица + подпись (для Energy screen).
- **IntentCard** — proactive-предложение с иллюстрацией + основным action + skip.

### Управление

- **BrightnessSlider** — горизонтальный, с ambient-градиентом внутри. Не просто линия — визуализация.
- **ColorWheel** — только на Device detail. HSV или CIE xy, whatever дизайнер решит.
- **Toggle** — большой (для основного on/off), маленький (в списках).
- **SceneChip** — компактная кнопка сцены.

### Ambient элементы (наша территория)

- **MotionPulse** — короткая волна/точка, появляется при motion event и затухает 3 сек.
- **AmbientGlow** — свечение тайла, отражающее «активность» комнаты.
- **StateBadge** — маленький индикатор в углу тайла (окно открыто, замок не заперт, батарея разряжается).

### Формы и типография

- **PromptField** — большое поле ввода с mic-кнопкой (для Automations).
- **CommandInput** — spotlight-поиск с автодополнением.

## 10. Motion & анимация

- **Все переходы — spring, не linear.** По ощущению — как ARKit interactions, а не Material-Design «300ms ease-in-out».
- **Ambient элементы дышат медленно** (2–4 секунды на цикл), не отвлекают.
- **События (motion, включение света) — мгновенны, но с плавным затуханием.**
- **Долгие таски (add device) — прогресс, а не спиннер.** Круг с прогрессом + текст того, что происходит в этот момент.

## 11. Состояния

Для каждого экрана — обязательно спроектировать:
- **Empty** — «ещё ничего нет» с CTA (для Home это первый экран после onboarding с 1 комнатой и 0 устройств; для Automations — «попробуй промпт»).
- **Loading** — skeleton, не спиннер.
- **Error** — устройство не отвечает / нет соединения / rule сломан. Спокойный тон.
- **Offline** — вся сеть недоступна. Показываем «локально доступно X» (мы local-first — это наша ключевая сила).
- **Guest / restricted view** — что видит гость или ребёнок.

## 12. Accessibility

- Все элементы — минимум **44×44pt** для тапа.
- Контраст — WCAG AA как минимум для основного текста, AAA для крупного.
- Цвет никогда не единственный сигнал — состояние всегда дублируется формой/иконкой/текстом (для дальтоников).
- Voice-first опция везде, где есть text-input.
- Screen reader labels — на каждый control.
- Dynamic Type — тексты масштабируются.

## 13. Локализация и голоса

Стартуем на русском и английском. Готовим тексты как ключи, не хардкоды. **Тон копирайта — тёплый, не робот, но не панибратский.** Примеры:

- Плохо: «Устройство успешно добавлено в систему.»
- Хорошо: «Готово. Свет в спальне работает.»

- Плохо: «Ошибка соединения с устройством. Код 503.»
- Хорошо: «Не могу дотянуться до лампы в кухне. Проверь, не выключен ли Wi-Fi роутер?»

## 14. Deliverables от дизайнера (список от нас)

Приоритезирую грубо: сначала #1, потом #2, потом #3.

1. **Home screen** — финальные макеты dark + light в 3 состояниях (утро/день/вечер + ambient активности).
2. **Room detail** — макет со всеми типами устройств (свет, розетка, датчики, замок).
3. **Add device flow** — main screen с камерой + список найденных.
4. **Automations screen** — с промптом, suggestion-card и 2–3 существующими правилами.
5. **Onboarding flow** — 5 экранов последовательно.
6. **Component library** — Figma-компоненты для #1–5.
7. **Style guide** — финальная палитра (light+dark), типографика, spacing, motion tokens.
8. **Empty/error/offline states** — для каждого из главных экранов.
9. **Energy screen** — макет с графиком, топ-3, аномалия.
10. **You / family mode** — макет управления профилями.

Не приоритет для v0.1: детальные экраны device settings, интеграции, магазин расширений. Оставим на v0.2.

## 15. Открытые вопросы для обсуждения

1. **Ambient view — 2D-план или абстрактная композиция?** 2D-план требует, чтобы пользователь его нарисовал (или мы дадим шаблоны). Абстрактная композиция (тайлы неровной сетки с цветом) — работает без разметки. Мой вкус — стартовать с абстрактной, план как v1.5.
2. **Реальная камера в Add Device — насколько глубоко?** OCR коробки? Scan Matter QR? Оба? Требует ML-инвестиций.
3. **Presence detection UI** — как показываем «дома / нет дома» для членов семьи. Приватность важна.
4. **Widgets на home screen устройства** — что показываем на iOS/Android widget? Одну комнату? Быстрый toggle?
5. **Apple Watch / WearOS** — стоит ли делать в v0.1 или подождать? Мой вкус — mock-up на watch делаем в v0.1, code — в v0.2.

## Приложение: HTML-наметки

Файл `ui-mockups.html` в этой же папке — 4 экрана как rough-wireframes с примерной палитрой и типографикой. **Это не финальный дизайн.** Это структура и иерархия, чтобы дизайнер увидел «как оно должно быть устроено», не «как оно должно выглядеть». Финальный visual — работа дизайнера.
